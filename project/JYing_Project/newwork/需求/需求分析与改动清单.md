## 0. 结论速览

1. **需求本质不是"加几个链接"，而是"扩领域 + 换抓取方式"**：分类从 2 个变成 5～6 个，
   而需求里约 **2/3 的站点没有可用 RSS**，现有"只吃 RSS/Atom"的抓取层撑不住。
2. **架构可以复用**：源列表、去重、归档、页面生成这套骨架不用推翻，改 4 个地方即可
   （分类体系、抓取层、源配置结构、页面分组）。
3. **不建议照单全收**：世界模型/端侧 AI 多为智库报告，不适合"每天抓资讯"；
   部分站点（The Robot Report、亿欧、EEWorld）有反爬。建议精选 12～15 个源 + 报告类改周更。
4. 粗估工作量：**P0 半天（分类扩 6 + 接入可用 RSS）、P1 1 天（通用 HTML 列表解析）、P2 半天（报告周更 + 跨源去重）**。

## 3. 必须改动的地方

### 3.1 分类体系：2 → 6（影响面最大）

现状是两个常量，散落在 CSV、TXT、MD、HTML、关键词表五处：

```python
CATEGORY_AI = "人工智能"
CATEGORY_EMBEDDED = "嵌入式/半导体"
CATEGORY_ORDER = (CATEGORY_AI, CATEGORY_EMBEDDED)
```

建议改为 6 个领域，并保留"AI"作为跨领域标签（同一篇文章可能既属 AI 又属机器人，
建议**领域单选 + AI 作为标记位**，避免多对多把页面搞复杂）：

| 领域 key | 显示名 | 覆盖需求 |
| --- | --- | --- |
| `ai` | 人工智能 | 原有 AI 源 |
| `embedded` | 嵌入式 / 硬件 | 硬件与嵌入式 |
| `auto` | 汽车与智能网联 | 汽车 |
| `robot` | 机器人 / 具身智能 | 机器人 |
| `medical` | 医疗科技 | 医疗 |
| `worldmodel` | 世界模型 / 端侧 AI | 前沿 |

连带要改：

- `CATEGORY_ORDER` 与排序逻辑；
- `KEYWORDS` 增加 `auto` / `robot` / `medical` / `worldmodel` 四套中英文关键词；
- 综合源（36氪、IT之家等）归类时从"二选一"变成"六选一"，按命中数取最高分；
- 页面标签 3 → 7（全部 + 6 领域），每个领域一个主色；
- 统计卡片从 4 个变成"总数 + 6 领域"或"总数 + 重点 4 个"。

### 3.2 抓取层：必须支持 HTML 列表页

现在 `Source` 只有 `name/url/category/strict`，抓取函数写死 `parse_feed()`。需求里过半站点没有 RSS，
需要把"取数据"抽象成策略：

```python
@dataclass(frozen=True)
class Source:
    name: str
    url: str
    domain: str                 # ai / embedded / auto / robot / medical / worldmodel
    kind: str = "rss"           # rss | html
    strict: bool = True
    list_selector: str = ""     # kind=html 时：列表项 CSS 选择器
    title_selector: str = ""    # 相对列表项
    link_selector: str = ""
    time_selector: str = ""
    max_items: int = 15
```

新增 `fetch_html_list()`：用 `requests` + 正则/`html.parser` 提取列表（项目坚持不引入 bs4/lxml 的话，
用标准库 `html.parser` 写个小解析器即可；若允许加依赖，`selectolax`/`parsel` 更省事——**需要你拍板**）。

要点：

- 摘要对列表页通常没有 → 允许 `summary` 为空，页面/CSV 不要留空字段的怪样子；
- 相对链接要 `urljoin`；
- 编码：中文站点常见 GBK/GB2312，需按 `<meta charset>` 或响应头解码；
- 时间可能只有 `MM-DD` 或"3 小时前" → 需归一化，推断年份；
- 单站选择器失效要能降级为空（不要抛异常拖垮整轮）。

### 3.3 数据与展示

| 位置 | 现在 | 改成 |
| --- | --- | --- |
| CSV 列 | `日期, 分类, ...` | 建议改为 `日期, 领域, 来源, 标题, 摘要, 链接, 发布时间`（旧文件向前兼容：读不到"领域"就按"分类"读） |
| TXT / MD 分组 | 两节 | 按 6 领域分节，空领域折叠 |
| index.html | 3 个标签 | 7 个标签 + 领域配色；搜索、日期、深色模式不变 |
| 统计 | 总数/AI/嵌入式/来源 | 总数 + 6 领域计数（手机上会挤，需横向滚动或只显示前 4） |
| 页脚 | 固定文案 | 可加"共 N 个源 / M 个领域" |

### 3.4 工程细节

- **限流**：源从 25 → 40+，并发 8 可能触发更多 403。建议按域名限速（`time.sleep` 或每域名串行），
  并给 `--workers` 上限。
- **耗时**：现在约 40 秒/轮；接入 HTML 站点后可能 2～4 分钟。任务计划超时已是 2 小时，够用，
  但单源 `--timeout` 建议区分（RSS 15s，HTML 20s）。
- **去重**：跨站转载（盖世/车云/第一电动同一条新闻）需要标题相似度去重，现有"按链接去重"不够。
- **失败可见**：源多了以后，控制台逐行打印会很长 → 保留日志文件 + 结尾汇总即可。
- **配置外置**：源配置建议挪到 `Demo/sources.json` 或 `sources.py`，改站不用动主逻辑。
- **文档**：README 的"资讯源清单/分类规则/页面功能"三节要同步。

## 5. 需要你确认的 4 件事

1. **是否允许引入新依赖**（如 `selectolax`/`parsel`）？不引入的话我用标准库 `html.parser` 写解析器，
   能用但选择器能力弱、维护成本高。
2. **列表页抓取可接受"只有标题+链接+时间，没有摘要"吗**？多数中文站列表页不给摘要，进详情页抓会翻倍请求、更容易被封。
3. **汽车、医疗要不要细分频道**？（如盖世"智能网联"vs"新能源"、OFweek 医械 vs 医疗 AI）
4. **世界模型/端侧 AI 是否接受"周更"**？这些领域本质是研究报告，每日抓取只能抓到零星新闻，性价比低。

## 6. 为什么不建议"20 个站全上"

- **一半以上没有 RSS**：每个站都要单独写选择器，站点改版就失效，长期维护成本高；
- **反爬集中**：EEWorld、The Robot Report、亿欧、车云都是硬骨头，投入产出比低；
- **内容重叠**：盖世/车云/第一电动在"智能驾驶"上高度重合，3 个源不如 1～2 个精选；
- **定位不同**：世界模型/端侧 AI 的信息形态是报告和白皮书，不是新闻流。

**推荐组合（12～15 个）**：

| 领域 | 保留源 |
| --- | --- |
| 人工智能 | 现有 14 个（可精简到 10 个） |
| 嵌入式/硬件 | CNX Software、Hackaday、EE Times、EE Journal、电子发烧友、21ic |
| 汽车 | 盖世汽车（智能网联）、第一电动 |
| 机器人 | 具身之家、The Robot Report（若能绕过 403） |
| 医疗 | OFweek 医械、Medical Economics（过滤后） |
| 世界模型/端侧 | EE Times TinyML、Edge AI Foundation（周更） |
