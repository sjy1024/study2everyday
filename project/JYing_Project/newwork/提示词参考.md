## 一、提示词原文

### P1｜需求：每日行业资讯爬虫（2026-10-22）

> 帮我写一个 Python 脚本。要求：脚本写到这个文件夹中 @Demo/
>
> 每天爬取 一些有关AI还有嵌入式相关的行业咨询。
>
> 把结果保存到我 D 盘的D:\AI\DSHworkspace\newwork文件夹里，按日期命名（比如 2026-10-22_news.csv 或 .txt）。
>
> 写好之后，请直接在这个工作区帮我运行测试一下，确保能成功抓到数据。

**要点**

| 维度 | 内容 |
| --- | --- |
| 目标 | 每天抓取 AI + 嵌入式行业资讯 |
| 落点 | 脚本放 `Demo/`，数据放 `D:\AI\DSHworkspace\newwork` |
| 格式 | 按日期命名，`.csv` 或 `.txt` |
| 隐含要求 | 要能"每天"跑 → 需要可重复执行、增量不丢数据 |
| 验收 | 不是"写完就行"，必须当场跑通、抓到真实数据 |

### P2｜追问：关机是否还能跑（2026-10-22）

> 我电脑关机也跑？

**说明**：这不是功能需求，而是对"每天"这个前提的澄清。结论是 Windows 任务计划程序
在本机关机/休眠时不会执行，只能靠补跑、云端或 BIOS 定时唤醒。

### P3｜调整：定时 09:30 + 更换输出目录（2026-10-22）

> 帮我改为每天九点半跑吧，如果电脑关机那就算了，然后把输出文件的路径改为D:\AI\DSHworkspace\newwork\worknews

**要点**

- 定时：每天 **09:30**（原方案未定时间）
- 取舍：关机那一次**允许跳过**，不做补跑
- 输出：`D:\AI\DSHworkspace\newwork\worknews`（数据与脚本分离）
- 一句话同时改了"调度"和"存储"两件事，属于典型的增量修正型提示词

**要点**

| 维度 | 内容 |
| --- | --- |
| 目标 | 把抓取结果做成可浏览的网页 |
| 位置 | 工作区根目录 `index.html` |
| 观感 | "好看" + **深色模式** |

**实际处理**：`file://` 下 JS 无法 `fetch()` 本地文件，所以改为把数据内嵌进 HTML，
并顺带补上 `news.md` 输出，保证"双击即看"。

## 二、提示词拆解

这四段话之所以有效，是因为覆盖了下面几件事，可以直接照抄这个结构：

1. **做什么**：抓什么主题、产出什么（脚本 / 数据 / 网页）。
2. **放哪里**：脚本目录、数据目录，写绝对路径或 `@文件夹`，避免歧义。
3. **什么形态**：文件格式、命名规则（`YYYY-MM-DD_news.csv`）、页面形态。
4. **怎么用**：每天定时、双击打开——把使用场景说清楚，实现方式自然对。
5. **怎么算完成**：明确要求"直接运行测试，确保能抓到数据"，这是最关键的一句。
6. **改需求时**：直接说"改成 X，Y 就算了"，把取舍一并给出。

## 四、下次可以补上的提示

按这次的经验，写同类脚本时提前加这几句，能少返工：

- **数据源**：优先用公开 RSS/Atom，列出具体站点；不要依赖需要登录或反爬严格的页面。
- **容错**：单源失败要跳过并记录，整体不能崩；网络超时要有重试。
- **去重**：同一天重复运行要合并、按链接去重，不能覆盖已有数据。
- **时区/时间**：声明"按 Asia/Shanghai 归档"，避免源站时间写错导致"未来时间"。
- **归档策略**：网页只放最近 N 天，历史留在 CSV，避免单文件越来越大。
- **隐私**：数据只存本机，不上传。

## 六、后续追加

新的提示词继续往下记，保持"原文 + 日期 + 要点"的格式即可：

### P5｜需求整理与分析（2026-11-04）

> @提示词参考.md 帮我整理我写这个项目的提示词到这个文件中
> @爬取网站.md 这是我新的需要爬取网站的需求，根据 我目前项目看一下哪里需要修改的，输出到"D:\AI\DSHworkspace\newwork\需求"这个文件夹中

**要点**

- 先给素材/参考文件（`@` 指定），再说要做什么，模型不用猜上下文；
- "根据我的项目看一下哪里需要修改" = 要**差异分析**，不是直接改代码；
- 明确输出位置，避免产物散落在工作区根目录。

**产出**：`提示词参考.md`（本文件）、`需求\需求分析与改动清单.md`（逐站探测 + 改动清单 + 分期）。

### P6｜按需求改造项目（2026-11-04）

> @需求\需求分析与改动清单.md @Demo\README.md 根据我这个需求和项目改进一下当前项目

**要点**

- 同时给"需求文档"和"现有项目说明"，模型改代码前就有完整约束；
- 用"改进一下当前项目"而不是重新生成，隐含要求**保持已有功能与风格**；
- 文档里列出的待确认项（依赖、摘要缺失、频道细分、周更）模型会取默认值推进，
  默认值都记在 README 的"已知限制"里，方便回头调整。

**结果**：6 领域、34 个源（26 RSS + 8 列表页）、跨天去重、网页 6 标签独立配色。
